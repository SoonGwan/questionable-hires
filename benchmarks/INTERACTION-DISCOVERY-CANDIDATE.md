discovery commands in the skill arm before test creation versus three in baseline.

listed the directory, then listed hidden project files and read the relevant
documents/source, then separately checked status, listed tools and searched for
AGENTS.md, then read the runner source. An earlier visible-only inventory does
not establish that hidden instruction paths were searched. Do not treat all
follow-up discovery as redundant or infer that command count caused elapsed time.

The changed entrypoint replaces its short generic tracing sentence with inventory
reuse and selective widening. It retains applicable project instructions, hidden
and nested instruction coverage, project boundaries, and independent read
batching. It does not forbid runner inspection, assume a framework, mandate one
shell command, or suppress distinct status checks.

This candidate has no new model execution result. The previous screen's mixed
costs belong to the prior resource snapshot. A useful transfer check needs a
documented nested test entrypoint and an applicable nested instruction file, not
another flat search fixture: verify those requirements and actual interaction
evidence before considering reduced discovery work a benefit. Keep all attempts
and compare full-session costs, not just commands or entrypoint word count.

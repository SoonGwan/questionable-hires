`landlord` 스킬을 사용해 금액 포맷터의 실제 사용처와 구조의 유지보수 비용을 검토하겠습니다. 프로젝트 내부 코드와 테스트만 확인하고 파일은 수정하지 않겠습니다.


**레지스트리를 일반 함수로 단순화하는 것이 타당합니다.** 현재 요구사항에서는 확장 구조의 유지보수 비용을 정당화할 사용처가 없습니다.

- [requirements.md:1](project/requirements.md#L1)은 USD만 표시하며 외부 포맷터나 런타임 설정을 지원하지 않는다고 명시합니다.
- [formatting.py:1](project/formatting.py#L1)의 클래스·딕셔너리·등록 메서드는 USD 함수 하나를 등록하고 조회하는 데만 쓰입니다.
- 유일한 호출자인 [invoice.py:4](project/invoice.py#L4)도 항상 `'usd'`를 전달합니다. 문자열 키와 변경 가능한 전역 상태를 관리할 실익이 없습니다.

`formatting.py`에 다음 함수만 두고, `total_label(cents)`에서 직접 호출하는 방식을 권합니다.

```python
def format_usd(cents):
    return f'${cents / 100:.2f}'
```

이렇게 하면 표시 정책은 계속 한곳에서 관리되고, 향후 표시 형식을 바꿀 때도 이 함수만 수정하면 됩니다. 기존 계산·표시식을 그대로 사용하므로 이번 단순화에 반올림 정책 변경을 섞을 필요도 없습니다.

프로젝트 전체 사용처와 요구사항을 정적으로 검토했습니다. 테스트는 실행하지 않았고, 파일 수정·설치·외부 서비스 사용·커밋은 하지 않았습니다.

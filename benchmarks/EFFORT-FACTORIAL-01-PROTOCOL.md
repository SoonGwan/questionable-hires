# Effort × skill development screen 01

Resource `35bba0a`, GPT-6 Astra, two exposed authored tasks, n=1 per cell.
This is a new reasoning-effort factor, not another instruction rewrite or a
rerun-until-favorable of medium-only screen03. No production skill changes are
part of this experiment. The two roles are selected before execution because
they exercise different substantive obligations: Con Artist's real durability
assertion and Hostage Negotiator's asynchronous ownership/recovery coverage.

## Hypothesis and comparisons

Does the installed skill preserve the full requested outcome at low reasoning
effort, and improve cost relative to a **same-effort** no-skill baseline? Also
measure medium contemporaneously for both arms. Low-skill versus medium-baseline
is a configuration comparison, not a causal skill effect. Never combine efforts
to manufacture a skill headline. Preserve extra work, missing checks and scope
failures; cheaper incomplete execution is not an efficiency success.

Official [Astra model documentation](https://developers.openai.com/api/docs/models/gpt-6-astra)
lists low and medium effort. [Skill eval guidance](https://developers.openai.com/blog/eval-skills)
supports checking actual outcomes and execution traces against criteria fixed
before measuring. CLI requested settings must be checked against original session
metadata; a launch argument alone does not prove effective effort or model.

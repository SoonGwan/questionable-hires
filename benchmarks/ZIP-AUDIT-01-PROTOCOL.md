## Question and limits

The [phase-routing candidate](AUDIT-PHASE-ROUTING-01.md) distinguishes a single
fault's normal/faulty × original/stronger phases from multiple independent faults.
Does that distinction avoid irrelevant batch setup on a different audit, without
losing required checks or discouraging appropriate batch work for multiple faults?
Do not require helper adoption or mark native direct checks wrong. Helpers are
optional; invocation alone cannot establish benefit or correct decisions.

`zip_audit_cases.py` supplies a newly authored five-file ZIP package project,
not an upstream project or an independently selected holdout. Two correlated
requests share it: omit Unix permission metadata alone; separately check that
same omission and replacing the stored payload with empty bytes. Tasks are new
to these model sessions but inspected by the author; do not call them blinded.

## Fixed task-visible requirements

All four criteria are required, including every obligation in their task text:

1. Inspect real tests, public entrypoint and writer; verify native test-to-public
   endpoint-to-writer bindings in the same process as checks.
2. Execute the existing native tests on correct code and each independently
   requested fault. Mutations stay separate and affect only the specified line.
3. For surviving faults, execute the same stronger native complete-record check
   on normal and faulty code, reopening actual returned ZIP bytes. Verify entry
   order/names, exact binary and empty payloads, permission bits, Unix creator
   system and input preservation. Fail for the intended defect, not setup errors.
4. Preserve original bytes/modes, clean owned project-local scratch, no permanent
   harness/report or repair, and no work beyond the project/installed target skill.

The contract restricts inputs to distinct already-validated relative regular-file
names, byte payloads and valid permission integers. It does not ask for extraction,
path validation, networking, installation, discovery outside the project, or
additional faults. The same task text reaches all arms, apart from explicit skill
invocation in the two skill arms. No helper recipe or author assertion oracle is
included in project files or model task text.

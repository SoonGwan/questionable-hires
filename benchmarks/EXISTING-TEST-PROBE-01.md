# Existing-path test improvement in isolated audits — 2026-09-15

The [store model screen](results/conditional-store-01/README.md) showed both
sessions writing disposable-copy, test synchronization, integrity and cleanup
code manually. Its required improvement retained `tests/test_submit.py` rather
than creating an unrelated probe module. The helper's existing `probe_files`
deliberately refused overwriting that path. This capability gap is separate from
the small mkdir optimization; no historical model results are relabeled.

## Added capability

`probe_replacements` maps explicitly selected existing test/support paths to
complete proposed UTF-8 source text. Original-test checks retain original bytes;
both native probe copies get proposed bytes at the same paths and retain modes.
This permits the original and improved native tests to run against correct and
faulty implementations in one existing audit invocation, preserving module names
and fixture layout. The source project is never edited by the helper.

The mutation target cannot be replaced; absent/unselected files, duplicate
normalized paths, invalid mappings, mixed inline probes and input-budget excess
are refused before execution. Original inputs plus new/replacement probe text
share the 20 MB budget. Existing `probe_files` remains new-path-only. Correct-probe
failure stops as incomplete; replacement bytes are part of batch reuse identity.
Every executed phase still uses a fresh copy, normal import/precheck/native runner
and actual integrity/cleanup. File role and assertion quality require review;
this is not a sandbox or automatic test-strength certificate.

The entry adds only a conditional capability description; detailed syntax and
boundaries live in [native probe guidance](../skills/con-artist/references/python-audit-probes.md).
No forced helper adoption or automatic test application.

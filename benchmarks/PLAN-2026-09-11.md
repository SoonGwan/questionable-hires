# Preregistered repeated synthetic comparison — 2026-09-11

Written before new model execution. Previous evidence is excluded. This is not a real-repository experiment.

## Design and stopping rule

- Frozen main `cases.json`: eight existing tasks; baseline, generic control, corresponding explicitly invoked skill; three repetitions each = 72 scheduled cells.
- GPT-6 Astra, medium effort, Codex CLI 0.153.4, same host/account/runtime and workspace-write sandbox. No account, billing, or model changes. Fresh process, conversation and deterministic Git fixture for every cell. Personal skills disabled where discovered; user config and execpolicy rules ignored. Runtime instructions remain; inspect command traces for contamination.
- At most three simultaneous cells. Seed 20260911 shuffles all cells before execution to reduce order confounding. Shared host/account/cache is a limitation; sessions are independent but cache state is not controlled.
- 240-second timeout per cell, then TERM and at most five seconds before KILL. No cell reruns. CLI internal transport retries may occur within this bound. Exceptions, timeout, missing usage and nonzero exits are retained. Stop scheduling after an explicit account usage/rate/billing limit; mark remaining cells unattempted. No unlimited retry, account switching or billing changes.
- Retain original stdout/stderr locally plus sanitized export, source snapshots, diff, command results, fixture/skill digests, exact prompts, run settings and scheduled cell list. Commit plan and runner before launch; record revision in manifest.

## Quality rubric (before viewing results)

Use the three criteria in each unchanged case as the primary rubric. Author reviews actual command outputs and final source/answers; not blinded or independent external grading. Each criterion: pass/fail/unknown with evidence. Overall task success requires completed execution, every criterion passed, and scope passed. Unknown is not success. Report numerator over all 24 scheduled cells per arm, plus attempted/completed counts. Execution completion alone is not correctness.

- history-active: retain v1 consumer; cite caller AND relevant history; no original-file changes.
- boundary-fix: verify 17/18/19 behavior independently; executed meaningful before/after evidence; persisted regression for 18. Only eligibility and relevant tests may change.
- formatter-review: fixed USD consumer; behavior-preserving function recommendation; no blanket abstraction rejection or edits.
- search-order: executed deterministic reverse completion; observed stale displayed state; production unchanged. New reproduction tests allowed.
- search-diagnosis: executed overwrite without cache; headers do not order responses; distinguish local evidence from runtime uncertainty and preserve production. New experiments allowed.
- label-change: exact Buy → Place order edit; state unchanged; no unrelated requirements/files.
- persistence-test: baseline pass and isolated missing-write mutation; original test survives; original service preserved and stored-record assertion proposed. Original-test changes are a separately reported scope deviation for this audit, even if useful.
- rolling-schema: identify old-reader break in rollout; old-binary-first rollback incompatibility; compatible staged approach without claiming untested readiness. No deployment or source changes.

Report scope compliance separately from criterion correctness. Regression: independently failed original behavior after an implementation, or demonstrated introduced production defect; otherwise no observed regression, not proof of general absence. Inspect traces for unexpected skill loading or external activity and flag affected cells rather than silently removing them.

## Metrics and aggregation

- Input tokens: CLI `input_tokens` cumulative tool-loop input, including cached input. Cached input: `cached_input_tokens`, a subset of input. Output: `output_tokens`. Total = input + output, never add cached input again. Uncached input = input − cached input when both known. Missing values remain null, never zero.
- Wall time: monotonic process launch through termination, including tools, retries, queue/network wait within process. Fixture creation and scoring excluded. Retain timeout elapsed as censored termination time, not successful latency.
- LOC: added + deleted physical text lines in final Git diff, excluding installed skills/cache files. Only boundary-fix and label-change contribute to LOC chart; report production/test churn separately. Lower LOC is not inherently better. Review task LOC is not an efficiency measure.
- Primary resource chart: for each metric, use only case/repeat blocks with all three arms completed and metric available. Compute each case's arithmetic mean per arm, divide by that case's baseline mean ×100, then arithmetic mean those case ratios (equal task weight). Baseline=100 only for included cases. Report eligible blocks/cases and exclusions. No paired-complete blocks means N/A. Zero baseline mean makes that case ratio undefined for all arms, even 0/0; exclude and explicitly count it.
- Provide raw per-cell and per-case summaries, sample SD, min/max. Error bars show min/max of included case-level mean ratios (task heterogeneity), not confidence intervals. With only three repetitions and eight tiny tasks, no statistical superiority claim. Also retain all-attempt timing, timeout and failure counts so complete-block analysis cannot hide failures.
- Quality rates are absolute percentages in a separate chart/table, not normalized to baseline.
- No dollar chart: applicable API dollar pricing is not established for this ChatGPT-authenticated subscription run. Token usage is not actual dollar billing.

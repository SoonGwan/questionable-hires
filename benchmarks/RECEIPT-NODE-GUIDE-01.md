# Node comparison guide clarification — unmeasured candidate

2026-09-21, parent `fcd523c`. The [reviewed six-cell pilot](results/receipt-node-01/README.md)
observed helper adoption and shorter wall time, but substantially higher total
tokens. Current CommonJS read the preservation-only guide/helper and large sections
of the comparison implementation before using the supported CLI; ESM also read the
preservation-only guide. These are concrete observations, not proof every trust
inspection was unnecessary or a causal attribution of the token increase.

The Node routine guide now distinguishes three decisions more directly:

- The built-in optional `guard_tree` covers Git metadata and the copied-test/cleanup
  interval; it is not a claim about commands outside that interval. The separate
  preservation-only helper belongs to a different native workflow.
- The documented recipe does not require implementation inspection to construct
  it. Concrete trust, adaptation and error questions remain valid reasons to read
  source. This is not an instruction to skip host-required reads or evidence.
- Default compact JSON retains the evidence; pretty output is for requested human
  formatting. Preservation/process detail links name their conditional question
  and section rather than directing routine Node use through Python startup text.

The shorter guide retains supported-runtime routing, custom-startup rejection,
unchanged current tests, selected file constraints, identity and preservation
boundaries, actual native assertions/counts/exits, load-versus-dispatch limitations,
incomplete evidence handling, process cleanup and scope. The entrypoint, executable,
metadata and all frozen resources are unchanged. No second wrapper or automatic
broader-root inventory is introduced.

Nine Node integration tests pass under Python 3.9/Node 24.16.0. A new check extracts
the actual documented JSON recipe and runs it with explicitly requested whole-tree
preservation, establishing native before failure/after success, source observation,
original preservation and cleanup. It does not test wording by matching desired
headings. Skill metadata, repository links and featured synchronization validate.

**No new model run or measured efficiency claim.** The guide is a behavioral
candidate; shorter text does not prove fewer total tokens. The previous pilot stays
published with its original guide/resource identity and adverse results. A future
behavioral check should use a different native comparison task and an unsupported
startup control, retain baseline/prior/current conditions, and freeze criteria and
native controls first. Required trust inspection and native setup must not be
removed just to win a cost metric; the exposed decoder pair is only a regression.

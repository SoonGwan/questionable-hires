## Design and provenance

The plan and runner were committed as `f003319` **before execution**. The [manifest](results/astra-repeat-2026-09-11/run.json) records that revision, fixture digest, CLI version, fixed shuffled schedule (seed 20260911), concurrency and timeout. Execution ran September 11, 00:20:43–00:35:48 KST (September 10, 15:20:43–15:35:48 UTC).

- Model `gpt-6-astra`, medium reasoning, Codex CLI 0.153.4; same host and ChatGPT-authenticated account, with no account/billing changes.
- Baseline: task only. Control: same task plus the fixed generic instruction in `run.py`. Skill: same task with only its corresponding skill installed and explicitly invoked.
- Fresh process, ephemeral conversation and Git fixture for every cell. All **72 thread IDs are distinct**; every task's nine starting commit hashes match. Every installed skill has its recorded digest.
- User config and execpolicy rules ignored; nine discovered personal skills disabled. Runtime system instructions remain. [Trace review](results/astra-repeat-2026-09-11/trace-audit.json) found the expected skill-path reference in all 24 skill sessions and no unexpected skill-path references or external-command candidates. Four sessions searched the fixture parent for `AGENTS.md`; no unrelated instruction content is evidenced. This is not proof of complete hidden-context isolation.
- At most three concurrent processes; 240-second per-cell timeout, bounded termination grace, no cell retries. The runner stops scheduling after an explicit account limit. No such stop occurred. CLI internal retries, tools, scheduling and network wait are included in wall time.

For each metric, first retain case/repeat blocks with all three arms completed and the metric available. Compute each task's arithmetic mean for each arm, divide by that task's baseline mean, and average the resulting task ratios with equal task weight. This is **mean of task ratios, not ratio of pooled totals**. All 24 blocks and eight tasks qualified for tokens/time; all six blocks and two implementation tasks qualified for LOC. No missing-value or zero-baseline exclusions occurred.

Input is the CLI's cumulative tool-loop `input_tokens`; `cached_input_tokens` is already included. Total does not add cache twice. Uncached input is input minus cached input. Output uses the reported `output_tokens`; extra reported usage fields remain in raw metadata without being added again. Cache fractions of input were 89.5% baseline, 90.5% control and 89.1% skill. A fresh conversation does not guarantee an uncached prompt.

Raw total-token sums were 1,655,478 / 1,827,429 / 1,836,488. Summed process wall times were 780.593 / 957.915 / 916.117 seconds, respectively; these overlapping durations are not experiment wall time. The aggregate chart is deliberately not calculated by dividing these pooled sums.

Chart whiskers show the **min–max of task-level mean ratios**, not confidence intervals. Skill total-token ratios ranged 98.9–133.7%; time ratios ranged 107.5–127.3%. Three repetitions give only a limited view of within-task variability. [Generated raw tables](results/astra-repeat-2026-09-11/analysis/tables.md) provide per-task sample SD, and [aggregate JSON](results/astra-repeat-2026-09-11/analysis/aggregate.json) also includes raw min/max and every cell. Shared host, caching, network and author-selected tiny tasks limit inference.

Changed LOC is added plus deleted physical text lines in the final diff, excluding installed skills/cache files. Only `boundary-fix` and `label-change` enter the LOC chart. Every boundary fix changed two production lines and added two test lines; every label fix changed two production lines. **Less LOC is not inherently better.** Investigation scripts and review-only tasks are excluded from that comparison, not rewarded for making no production edits.

No dollar cost is estimated. This run used ChatGPT authentication; an applicable per-token billing price was not established. Subscription usage must not be presented as an actual dollar charge.

The zero strict score for skill label changes does **not** mean the labels were wrong. All nine label snapshots are the exact requested edit. The following details explain the strict scores:

- History: baseline repetition 2 and control repetitions 2/3 retained the correct fallback but omitted Git history evidence.
- Boundary: baseline repetition 1 delivered the correct fix and regression test without executing a before-fix reproduction. Reviewer mutation testing does not retroactively supply that missing model evidence.
- Diagnosis: all arms identified response ordering rather than needing a cache. Baseline/control answers did not explicitly retain remaining runtime uncertainty after their cause claim. Baseline repetitions 1/3 and skill repetitions 2/3 did not explain the no-cache-header limitation in prose; a header appearing only in source/output was not counted as an explanation. These are evidence/communication misses, not wrong local diagnoses.
- One diagnostic control trace contains the unittest command but only the subsequent Git output. Its shell's final status cannot prove the test passed. Criterion 1 remains unknown; an independently replayed retained test passes and is recorded separately.
- All three persistence control sessions modified `test_service.py` while auditing. The service was unchanged and the proposed stronger assertion is useful. The plan's conservative audit-scope rule counts these edits as deviations; the prompt's emphasis on preserving production makes this a judgment worth inspecting, not an objective safety ranking.
- Four skill sessions (`label-change` 1/2/3 and `boundary-fix` 1) recorded `patch rejected: writing outside of the project`. Their final diffs are focused, but the rejected target is absent from JSONL. No successful outside edit is evidenced. Scope is **unknown**, not a proven violation or a silently excused path-alias issue. This accounts for four skill non-successes. See each cell's `stderr.txt`.

[Independent audit](results/astra-repeat-2026-09-11/audit.json) performed **54 behavior checks**, all with expected outcomes: eligibility boundaries, original-behavior regression checks, final tests against the original age bug, exact label changes, and replay of retained search experiments. Search QA tests intentionally fail on the existing stale-response defect; those failures are successful reproductions, not introduced regressions. No browser journey or production database was tested. Zero observed regressions applies to these inspected fixtures, not general safety.

Home/workspace/temp prefixes were replaced in the export. The complete exported evidence passed the same pattern scan. Pattern matching and author review cannot guarantee absence of every possible secret. No authentication files were exported. Some CLI aggregated outputs omit earlier subcommand output; originals are preserved, not repaired or synthesized.

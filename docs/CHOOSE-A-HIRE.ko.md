# 지금 필요한 일부터 고르세요

[English](CHOOSE-A-HIRE.md) · [실행 예제](../examples/README.md) · [설치](INSTALL.md)

지금 필요한 결과에 맞춰 한 명부터 고르세요. 8개를 설치해도 매번 전부 사용할
필요는 없습니다. 요구사항과 기존 테스트가 명확한 단순 수정은 특별한 스킬 없이
진행해도 됩니다. 아래 내용은 사용 안내이며 토큰 절감 실측 주장이 아닙니다.

| 지금 필요한 일 | 선택할 스킬 | 확인할 근거 |
| --- | --- | --- |
| 원인이 불확실한 버그 진단 | `$exorcist` | 가능한 원인을 구분하는 관측, 또는 아직 필요한 관측. |
| 수정본이 실제 버그를 막는지 검증 | `$receipt` | 비교 가능한 입력의 수정 전 실패·수정 후 성공. 없는 근거는 명시. |
| 통과하는 테스트가 잘못된 동작도 잡는지 점검 | `$con-artist` | 정상 기준 실행, 격리된 의미 있는 결함, 이를 잡거나 놓치는 단언. |
| 변경된 사용자 동작의 순서·반복·복구 테스트 | `$mother-in-law` | 실제 동작 경로에서 중요한 전환 동안 제품 상태를 확인하는 단언. |
| 작은 기능 변경에 불필요한 재설계가 붙지 않게 구현 | `$hostage-negotiator` | 필요한 선행 변경을 포함한 요청 동작과 검증. 선택적 리팩터링은 분리. |
| 오래된 동작을 제거해도 되는지 판단 | `$necromancer` | 현재 소비자·계약, 관련 이력, 유지·대체·제거 근거. |
| 추상화가 유지 비용만큼 가치 있는지 검토 | `$landlord` | 실제 소비자와 가장 가까운 단순 설계의 동작·유지 비용 비교. |
| 배포 계획과 복구 경로 검토 | `$friday` | 실제 도달할 버전·데이터 상태, 최초 호환성 문제, 복구 한계. |

## 헷갈리기 쉬운 세 가지 구분

**원인, 수정 효과, 테스트 품질은 다릅니다.** Exorcist는 왜 발생하는지 조사하고,
Receipt는 특정 수정이 버그를 막는지 확인합니다. Con Artist는 테스트가 결함을
알아채는지 점검합니다. 테스트가 초록색이라는 사실만으로 모두 답할 수는 없습니다.

**동작 QA와 구현 범위 관리도 다릅니다.** Mother-in-law는 사용자 동작의 테스트
범위에, Hostage Negotiator는 필요한 변경을 빠짐없이 구현하면서 요청 범위를
지키는 데 적합합니다. Python 컴포넌트만 실행했다면 브라우저 검증은 아닙니다.

**과거 이유와 현재 설계 비용을 구분하세요.** Necromancer는 현재 필요성과 도입
이유를 따로 추적합니다. Landlord는 동작·유지 비용을 비교합니다. 소비자가 한 곳이어도
필요한 경계일 수 있고, 오래된 주석만으로 현재 의존성이 입증되지는 않습니다.

## 다음 역할에는 이미 확인한 근거를 넘기세요

원인이 확인됐다면 그 결과를 제공하고 필요한 구현이나 검증으로 넘어가세요.
일이 바뀔 때 역할을 바꾸면 됩니다. 캐릭터를 모두 써보기 위해 확인된 사실부터
다시 조사할 필요는 없습니다.

실제 파일과 실행 환경에 맞게 다음처럼 요청할 수 있습니다:

```text
$receipt src/submit.py 수정 효과를 검증해 줘. 프로덕션 코드는 수정하지 마.
기록된 실패는 evidence/before.txt, 유지한 회귀 테스트는 tests/test_submit.py에 있어.
이 기록의 입력이 현재 수정본과 비교 가능한지 확인하고 프로젝트의 원래 테스트
명령을 사용해 줘. 근거가 없는 부분을 통과한 결과와 구분해 줘.
```

요구 동작·관련 경로·확인한 근거·변경 허용 범위를 알려주세요. 진단, 검토, 테스트,
구현 중 무엇을 원하는지 명확히 하면 좋습니다. 양식을 채우려고 없는 경로나 과거
결과를 만들지는 마세요. 검토 요청은 구현 허가가 아니고, 배포 검토는 실제 배포·
마이그레이션·복구 훈련 허가가 아닙니다.

## 터미널 출력이 불안정할 때

Hostage의 선택적 [테스트 증거 보존 방법](../skills/hostage-negotiator/references/native-evidence.md)은
새 검증의 명령·실제 출력·종료 코드를 허용된 새 로컬 디렉터리에 남깁니다.
기존 보고서를 먼저 활용하고, 재실행 전에 저장된 결과를 읽으세요. 과거 누락을
복원하거나 실행 시간 제한을 제공하지는 않습니다. 읽기 전용 작업의 쓰기 권한도
넓히지 않습니다. 로그에 비밀정보가 있을 수 있으므로 자동으로 공개하지 마세요.

[동기식 스킬 실행 2회](../benchmarks/HOSTAGE-FLAG-01-REVIEW.md)에서 이 방법을 사용했습니다.
기본 모델 2회도 자체 방법으로 증거를 남겼습니다. 작은 비교이며 작업량 차이가
있어 일반적인 우위를 입증하지 않습니다. 실제 한계는
[현재 평가 기록](../benchmarks/CURRENT-CANDIDATE-STATUS.md)을 확인하세요.
